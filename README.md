# うちの子がいちばん強い

2人で遊ぶブラウザ対戦ゲーム。それぞれが「うちの子」（画像か文章）を1〜3体出し、審判AIが鑑定してファイターにし、交代ありのターン制チームバトルで戦わせます。
審判AIの口ぐせは「……それ、強いの？」。

- 追加費用なし：AIの鑑定は、ホストがチャットAIに手作業で貼り付けて行います（API は使いません）
- 画像を読めるチャットAIなら何でも使えます（Claude、ChatGPT、Gemini など）
- 通信は WebRTC の P2P（PeerJS）。ホストのブラウザが進行役です
- 3人目以降が入ると観戦になります

## 遊び方

1. **ロビー**：ホストが名前を入れて「部屋を作る」→ 招待URL（またはルームID）を相手に送る。
   ホストが **1人あたりの体数（1〜3体）** を決める（2人とも同じ数）
2. **提出**：2人がそれぞれ、決めた数だけ画像か文章を提出（1体ごとに画像か文章を選べる）
3. **鑑定**（ホストの作業）
   1. 「画像をコピー」→ チャットAIの入力欄で Ctrl+V（名前ラベル付きのコラージュ画像。1人1行、複数体なら「たろう #1」「たろう #2」…）
      - 画像のコピーに対応していないブラウザでは、自動で保存に切り替わるので添付してください
   2. 「依頼文をコピー」→ 同じ入力欄に貼って送信（文章で提出された内容もここに全文入ります）
   3. 返ってきた `UCHINOKO2:…` という文字列をコピーして「クリップボードから読み込む」
      （貼り付け欄に貼っても、その時点で自動で読み込みます）
      - ホストもプレイヤーなので、鑑定結果は圧縮・符号化して返すよう指示文で頼んでいます（ぱっと見では読めません）
      - 読み込み後もホストの画面に中身は表示しません
      - 範囲外の数値は丸め、足りない項目は補います
      - 以前の `UCHINOKO1:…` 形式やそのままの JSON も読み込めます
   4. 「結果発表へ」
4. **結果発表**：各プレイヤーには**自分のチームだけ**が見えます（相手はシルエット）。ここで**先発**を選びます。
   相手の能力値や技はデータとしても送らないので、開発者ツールでも見えません。観戦者には全部見えます
5. **バトル**：各自が自分の端末で「技」か「こうたい」を選びます
   - 交代は技より先に行われ、交代したターンは攻撃できません。引っ込めると能力変化としびれは消えます
   - 技は、場に出ている子のすばやさ順に出ます
   - 相手より速いと、その差に応じて相手の技をかわしやすくなります（差1につき0.4%、最大30%）
   - 倒れたら控えから次の子を選んで出します（相手は待ちます）
   - 相手の子の名前と属性は、場に出たときに初めて分かります。技は使われたときに分かります
   - 相手のチームを全員倒したら勝ち
6. **決着**：リザルトで両チームの鑑定結果が公開されます

### チャットAI側の準備

**どのチャットAIでも使えます。** 必要なのは「画像を読めること」だけです。

- **おすすめ**：Claude のプロジェクト、ChatGPT のプロジェクト／カスタム GPT、Gemini の Gem など、
  指示を保存できる機能に [prompt/appraisal-instructions.md](prompt/appraisal-instructions.md) の中身を入れておく。
  以降は新しいチャットで画像と依頼文を送るだけです
- **そういう機能がない場合**：鑑定画面で「指示文も含める」にチェックを入れてから「依頼文をコピー」すると、
  指示文と依頼文をまとめて1回で貼れます
- **ネタバレ防止の圧縮・符号化**には、AI のコード実行機能（Claude の分析ツール、ChatGPT のコード実行など）を使います。
  コード実行ができない AI では JSON のまま返ってきますが、ゲームはそれも読み込めます（その場合ホストには中身が見えます）
- AIへの出力形式は、項目名を短くした「簡略形式」です（返答の長さは以前の形式の約4分の1）

## 公開（GitHub Pages）

PeerJS は HTTPS（または localhost）で配信されたページが必要です。

1. GitHub で新しいリポジトリを作り、このフォルダの中身を push する
   ```bash
   git init
   git add .
   git commit -m "first commit"
   git branch -M main
   git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
   git push -u origin main
   ```
2. リポジトリの Settings → Pages → Build and deployment で
   Source を「Deploy from a branch」、Branch を `main` / `/ (root)` にして Save
3. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます

## ローカルで試す

ES モジュールを使っているので、`index.html` を直接開くのではなくローカルサーバー経由で開いてください。

```bash
python -m http.server 8791
```

`http://localhost:8791/` を2つのタブで開けば、1台で通しの動作を確認できます。
鑑定画面の「（テスト用）サンプルを入れる」で、チャットAIを使わずにランダムな鑑定結果を入れられます。

## 構成

| ファイル | 役割 |
|---|---|
| `index.html` / `style.css` | 画面 |
| `js/main.js` | 画面遷移と進行（ホストは状態の正本を持ち、変更のたびに全員へ配信） |
| `js/net.js` | PeerJS 接続。`PEER_OPTIONS` を書き換えれば自前のシグナリングサーバーに切り替え可 |
| `js/media.js` | 画像の縮小、コラージュ書き出し、依頼文の生成 |
| `js/appraisal.js` | 鑑定結果 JSON の取り出し・検証・補正 |
| `js/battle.js` | ダメージ・命中・相性・効果・交代の計算（ホストだけが実行） |
| `js/rules.js` | 属性一覧、相性表、上限値 |
| `js/sfx.js` | 効果音（Web Audio API で合成。音声ファイルなし）。右上の「音：ON/OFF」で切り替え、設定はブラウザに保存 |
| `prompt/appraisal-instructions.md` | チャットAIに渡す鑑定用の指示文 |

## ルールの要点

- ジョーク寄りなので上限はゆるめ：HP 60〜250、こうげき／ぼうぎょ／すばやさ 各1〜120、HP込みの4つの合計 400 以下（超えたら比率を保って縮める。HP だけ盛れば得、にならないように）
- 技：4つ、威力 0〜150、命中 30〜100。技名と中身は画像・文章から読み取った特徴をもとに AI が決める。うち1〜2個は自分と違う属性
- 属性：炎 / 水 / 草 / 雷 / 氷 / 地 / 闇 / 光 / 無（相性表は `js/rules.js`。バトル画面の「相性表」ボタンでも見られる）
- 弱点は属性で決まる（AIは決めない）

  | 属性 | 弱点 |
  |---|---|
  | 炎 | 水・地 |
  | 水 | 草・雷 |
  | 草 | 炎・氷 |
  | 雷 | 地 |
  | 氷 | 炎 |
  | 地 | 水・草・氷 |
  | 闇 | 光 |
  | 光 | 闇 |
  | 無 | なし |

- ダメージ ≒ 威力 × 0.4 × (攻撃+40)/(防御+40) × 相性 × 同属性1.2 × 審判のいらだち × 乱数0.85〜1.0（急所 1/16 で1.5倍）
- 弱点を突くと **2倍**、しかも相手の防御を**3/4**として計算（硬い子への切り札）。いまひとつは 0.5倍
- **審判のいらだち**：1体戦は8・2体戦は18・3体戦は28ターン目から、毎ターン全員の与ダメージが +15%（3ターンごとに審判がぼやく）
- AIが決める「苦手な属性」（追加倍率）は今は使っていない。`js/rules.js` の `AI_WEAKNESS_MULT` を 1.25 などにし、指示文に `w` を戻せば再導入できる
- 効果：`heal` 回復 / `buff_atk` `buff_def` 能力アップ / `debuff` 相手の攻撃・防御ダウン / `stun` 1回行動不能（連続しびれ防止あり）
- 回復量：威力0の回復技は最大HPの25%、威力ありの回復技は与えたダメージの30%
- 使用回数（ゲームが自動で決める。`js/rules.js` の `skillPP`）

  | 技 | 回数 |
  |---|---|
  | 威力 〜40 / 〜60 / 〜80 / 〜100 / 〜120 / それ以上 | 15 / 10 / 8 / 5 / 3 / 2 |
  | 追加効果つきの攻撃技 | 上の表から −1 |
  | 吸収（威力ありの回復技） | 最大 4 |
  | 命中60以下 | +1 |
  | 変化技：回復 / しびれ / 能力アップ / 弱体 | 3 / 5 / 6 / 8 |

- 全部の技を使い切ると「わるあがき」（威力35、使うたびに自分の最大HPの1/6を失う）しか出せない
- 相手の残り回数は見えません
- 80ターンで決着がつかなければ、チーム全体の残りHPの割合で判定

## 既知の制限

- ホストがページを閉じたり再読み込みしたりすると部屋は消えます（状態はホストのブラウザにだけあります）
- 参加者が切断した場合は、同じ名前で入り直すと復帰できます
- 一部の企業ネットワークなど、P2P 接続が通らない環境では TURN サーバーが必要になることがあります
